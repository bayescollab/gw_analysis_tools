Adding a New Waveform Model to GWAT
=====================================

This document describes the steps required to integrate a new waveform model
into GWAT's parameter estimation pipeline, using the EFPE integration as a
concrete reference. It covers the code changes needed after the library has
been vendored and the CMake build has been set up.


1. Parameter Packing/Unpacking (src/fisher.cpp)
-----------------------------------------------

1a. unpack_parameters
    This function converts a gen_params_base<double> back into the flat MCMC
    parameter vector. It is called by calculate_derivatives (the numerical
    Fisher routine) to obtain the parameter vector before perturbing each
    element for finite differencing. If a model has no branch here, the
    parameter vector will be left uninitialised, causing the perturbed
    waveform calls to receive garbage masses and crash.

    Add a branch inside BOTH the non-sky-averaged (!sky_average) AND the
    sky-averaged (intrinsic) blocks.

    Non-sky-averaged MCMC branch (mirrors repack_parameters layout):
        parameters[0..14] = RA, sin(DEC), psi, cos(iota), phiRef, tc,
                            ln(DL), ln(Mc), eta, a1, a2,
                            cos(tilt1), cos(tilt2), phi1, phi2
        Additional model-specific entries at [15+].

    Sky-averaged MCMC branch (intrinsic-only, mirrors PhenomPv2 intrinsic):
        parameters[0..7] = ln(Mc), eta, a1, a2,
                           cos(tilt1), cos(tilt2), phi1, phi2
        Additional model-specific entries at [8+].

1b. repack_parameters
    This is the inverse: maps the flat MCMC vector to gen_params_base fields.
    The generation method string is prefixed with "MCMC_" when called from
    the MCMC likelihood, so use find() to match.

    Add a branch inside both the non-sky-averaged AND sky-averaged blocks,
    mirroring the layout documented in unpack_parameters above.

    For the non-sky-averaged layout, follow the IMRPhenomPv2 MCMC reference:

        [0]  RA
        [1]  sin(DEC)
        [2]  psi
        [3]  cos(iota)        -> acos applied
        [4]  phiRef
        [5]  tc
        [6]  ln(D_L)          -> exp applied
        [7]  ln(Mc)           -> exp applied
        [8]  eta
        [9]  a1               (spin1 magnitude)
        [10] a2               (spin2 magnitude)
        [11] cos(tilt1)       -> acos applied
        [12] cos(tilt2)       -> acos applied
        [13] phi1             (spin1 azimuthal angle in the L frame)
        [14] phi2             (spin2 azimuthal angle in the L frame)

    Spins are stored in Cartesian coordinates in gen_params_base. Use
    transform_sph_cart to convert from spherical (a, theta, phi) to Cartesian.
    Clamp the cos(tilt) arguments to [-1, 1] before calling acos, as the
    Fisher proposal can step outside this range.

    Additional model-specific parameters follow after index 14.

    Model variants (e.g. a circular limit) can be handled inside the same
    branch with a nested find() check rather than a separate branch:

        else if(generation_method.find("<MODEL>") != std::string::npos){
            if(generation_method.find("MCMC") != std::string::npos){
                // ... common parameter mapping ...
                if(generation_method.find("circular") != std::string::npos){
                    a_params->e_start = 0;
                } else {
                    a_params->e_start = avec_parameters[15];
                }
            }
        }


2. MCMC Preparation (src/mcmc_gw.cpp)
-----------------------------------------------

2a. PTMCMC_method_specific_prep
    Add branches that recognise the model name and parameter-space dimension,
    print the parameter list, and set *intrinsic. Add these before the
    generic else{} exit block. Use an early return to avoid falling through
    to the error exit:

        if(generation_method.find("<MODEL>") != std::string::npos
            && (dimension - totalmod) == <N>)
        {
            std::cout << "Sampling in parameters: ..." << std::endl;
            *intrinsic = false;
            return;
        }

    Add one branch per supported dimension (e.g. a circular variant at
    dim=15, an eccentric variant at dim=17).

2b. Fisher regularization in MCMC_fisher_transformations
    This function adds prior-width regularization terms to the diagonal of the
    Fisher matrix. Without these, parameters that are weakly constrained by the
    likelihood (near-zero Fisher elements) make the matrix ill-conditioned. When
    the block Fisher is inverted for the proposal covariance, a near-singular
    matrix causes huge proposed steps across all parameters in the block, not
    just the weakly constrained ones.

    For models using the precessing-spin layout (indices 11-14: cos_tilt1,
    cos_tilt2, phi1, phi2), add the model name to the condition that
    regularizes those entries. This must be done in all four Fisher
    transformation sites across the codebase:


        src/mcmc_gw.cpp           MCMC_fisher_transformations      non-intrinsic branch
        src/mcmc_gw.cpp           MCMC_fisher_transformations      intrinsic branch
        src/mcmc_gw.cpp           MCMC_fisher_wrapper              non-intrinsic branch
        src/mcmc_gw.cpp           MCMC_fisher_wrapper              intrinsic branch

    In each site the pattern is:

        if(generation_method.find("PhenomPv2") != std::string::npos ||
           generation_method.find("PhenomPv3") != std::string::npos ||
           generation_method.find("<MODEL>")   != std::string::npos){
            fisher[11][11] += 1./4;   // non-intrinsic: indices 11-14
            fisher[12][12] += 1./4;
            fisher[13][13] += 1./(4*M_PI*M_PI);
            fisher[14][14] += 1./(4*M_PI*M_PI);
        }

    The intrinsic branch uses indices 4-7 instead (different layout); add the
    same model condition there too.

    This is particularly important at the circular limit, where spin orientations
    are weakly constrained and the corresponding Fisher elements are near-zero.

2c. Proposal setup in PTMCMC_MH_dynamic_PT_alloc_uncorrelated_GW
    The five proposals are:
        propArray[0]  gaussianProposal
        propArray[1]  blockDifferentialEvolutionProposal  (or DE for intrinsic)
        propArray[2]  KDEProposal
        propArray[3]  blockFisherProposal
        propArray[4]  GMMProposal

    For models that follow the standard extrinsic/intrinsic split with 7
    extrinsic parameters (RA, sin DEC, psi, cos iota, phi_ref, tc, ln DL),
    the existing else{} branch at the end of the if/else chain already
    provides the correct 3-block structure for all five proposals. No
    additional block is needed.

    Add an explicit branch only if the model requires a different block
    structure (e.g. a different extrinsic/intrinsic split, or additional
    parameter blocks as in EA_IMRPhenomD_NRT).

    The blockFisherProposal calls fisher_autodiff when the user sets
    fisher_AD=true. If the model does not support ADOL-C, this will throw
    at runtime. Set fisher_AD=false in the user parameters for such models.
    The numerical Fisher (fisher_AD=false) works with any model that has a
    double-precision waveform.


3. Generation Method String Conventions
----------------------------------------
Use descriptive substrings that compose predictably:

    "<MODEL>"              base model, arbitrary frequency grid
    "<MODEL>_uniform"      uniform frequency grid (faster for MCMC)
    "<MODEL>_circular"     circular limit (e=0), fewer sampled parameters
    "<MODEL>_circular_uniform"  both

Dispatch is always done with find(), so any string containing "<MODEL>"
routes to the model's branch. More specific variants (e.g. "_circular")
are checked inside the branch with a nested find().


4. Checklist for a New Model
------------------------------
[ ] Add unpack_parameters branch (non-sky-averaged + sky-averaged) in src/fisher.cpp
[ ] Add repack_parameters branch (non-sky-averaged + sky-averaged) in src/fisher.cpp
[ ] Add dimension branch(es) in PTMCMC_method_specific_prep
    (extrinsic dim=N with *intrinsic=false; intrinsic dim=M with *intrinsic=true)
[ ] Add proposal branch in PTMCMC_MH_dynamic_PT_alloc_uncorrelated_GW
    (only if block structure differs from the standard 7/rest split)
[ ] Add Fisher regularization for spin-angle indices in all six sites
    (see section 2b for the full list of files and functions)
[ ] Add any new gen_params_base fields to include/gwat/util.h with defaults
[ ] Verify fresh build passes with no new errors
